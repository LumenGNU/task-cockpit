## Pinned Tasks

Секция **Pinned** в дереве задач — быстрый доступ к закреплённым задачам. Отображается отдельной веткой в начале дерева, не влияя на основной список.

![????](media/pinned-view.png)


### Поведение

- Задача остаётся видимой и в основном списке, и в секции Pinned
- Закреплённые задачи игнорируют поле `hide` — видимы всегда
- Порядок в Pinned определяется порядком в настройках, а не в файле задач
- Все действия доступны: запуск, остановка, терминал, переход к определению
- Статус-бейджи работающих задач отображаются как в основном дереве


### Как использовать

- **Закрепить**: правый клик на задаче → **Pin Task**
- **Убрать**: правый клик на задаче (в Pinned или в основном списке) → **Unpin Task**
- **Порядок**: определяется массивом в настройках; (drag-and-drop рассматривается)


### Сжатие путей

Секция Pinned повторяет иерархию основного дерева (с учётом [`segmentSeparator`](#segmentseparator) и [`useGroupKind`](#usegroupkind)), но сжимает промежуточные узлы без ветвления — объединяет их в один, отображая через `›`.

Пример при сепараторе `:` с тремя закреплёнными задачами
`build:frontend:dev:watch`, `build:frontend:dev:lint`, `build:backend:compile`:

Основное дерево:
~~~
build
├─ frontend
│  └─ dev
│     ├─ watch
│     └─ lint
└─ backend
   └─ compile
~~~

Pinned (режим `normal`):
~~~
build
├─ frontend › dev
│  ├─ watch
│  └─ lint
└─ backend
   └─ compile
~~~

Pinned (режим `aggressive`):
~~~
build
├─ frontend › dev
│  ├─ watch
│  └─ lint
└─ backend › compile
~~~

Разница: в режиме `normal` сжимаются только промежуточные узлы — задача всегда остаётся отдельным элементом дерева. В режиме `aggressive` задача тоже может стать частью сжатого пути, если она единственный потомок родителя.

В примере выше `backend` имеет единственного потомка `compile`. В `normal` — два узла; в `aggressive` — один: `backend › compile`.


### Идентификация

Закреплённая задача хранится как пара **label + имя папки** в настройках VS Code. В single-root воркспейсах имя папки опускается.

Список доступен в settings — можно отредактировать или почистить вручную.


### Потерянные ссылки

Если закреплённая задача не найдена в текущем списке задач, она отображается как **broken** — визуально отмечена и размещена в начале секции Pinned. Это позволяет заметить сломанные ссылки, вместо того чтобы терять молча.


### Настройки

#### `taskCockpit.pinned.visibility`

Видимость секции Pinned.

- `auto` (по умолчанию) — видима при наличии хотя бы одной закреплённой задачи (включая broken). Скрывается автоматически, когда список пуст.
- `hide` — скрыта безусловно.


#### `taskCockpit.pinned.compression`

Режим сжатия путей в секции Pinned.

- `normal` (по умолчанию) — сжимаются только промежуточные узлы. Задачи всегда отображаются отдельно.
- `aggressive` — задачи тоже включаются в сжатие, если являются единственным потомком.
